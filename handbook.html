Jobsheet 01

Dasar HTML dan Struktur SIMPUS-Mini

HTML digunakan untuk membentuk kerangka halaman: navigasi, judul, konten, tabel, formulir, dan footer.

Materi utama

  • Struktur dokumen HTML dengan <!DOCTYPE html>, <head>, dan <body>.
  • Elemen semantik seperti <header>, <nav>, <main>, <section>, dan <footer>.
  • Tabel data menggunakan <table>, <thead>, <th>, <tbody>, dan <td>.
  • Formulir memakai <label>, <input>, <select>, dan tombol.
  • Menu navigasi yang konsisten agar halaman buku dan anggota bisa saling dibuka.

Perubahan yang dikerjakan

  1. Menambahkan tautan “Daftar Anggota” dan “Tambah Anggota” ke menu navigasi.
  2. Menambahkan dua baris data buku dengan menyalin struktur <tr>...</tr> lalu mengganti nilainya.
  3. Menambahkan kolom “Tanggal Bergabung” ke tabel anggota dengan pasangan <th> dan <td>.
  4. Menambahkan field Email dengan <input type="email"> agar browser memeriksa format email dasar.
Inti pembelajaran: jumlah kolom pada header tabel harus sesuai dengan jumlah sel data pada setiap baris. Periksa juga jalur tautan relatif, terutama ketika file berada di folder buku/ atau anggota/.
Jobsheet 02

CSS Dasar dan Konsistensi Desain

CSS mengatur tampilan HTML, termasuk warna, jarak, ukuran, susunan elemen, dan keadaan interaktif.

Materi utama

  • Selector dan deklarasi CSS: selector, property, dan value.
  • Warna tema yang digunakan secara konsisten pada header, judul section, tombol, dan header tabel.
  • Flexbox untuk navigasi serta flex-wrap: wrap agar menu dapat berpindah baris ketika ruang terbatas.
  • CSS Grid untuk kartu statistik.
  • Pseudo-class dan selector berdasarkan posisi, seperti :first-of-type dan :last-of-type.

Praktik pada proyek

  1. Mengubah warna biru tema menjadi hijau tua dan mengamati konsistensinya di semua komponen.
  2. Menambah kartu statistik keempat dan menyesuaikan grid dari tiga menjadi empat kolom.
  3. Menambahkan tombol “Detail” di antara tombol Edit dan Hapus, kemudian memeriksa warna serta selector tombol.
  4. Mengecilkan jendela browser untuk melihat perilaku navbar.
Tips: simpan warna utama sebagai CSS custom property, misalnya --green-900. Dengan begitu, perubahan tema dapat dilakukan dari satu tempat.
Jobsheet 03

Responsive Design dan Media Query

Tampilan responsif membuat halaman tetap nyaman dipakai di desktop, tablet, dan ponsel.

Konsep penting

  • @media digunakan untuk menerapkan aturan CSS pada ukuran layar tertentu.
  • max-width biasanya digunakan untuk menyesuaikan tampilan pada layar yang lebih kecil.
  • min-width dapat digunakan untuk pendekatan mobile-first: mulai dari tampilan kecil, lalu menambahkan peningkatan untuk layar lebih lebar.
  • Kontainer tabel atau kode panjang perlu dibungkus agar tidak merusak lebar halaman.
  • Menu hamburger perlu memperhatikan urutan elemen HTML dan selector sibling seperti ~.

Praktik pada proyek

  1. Menambah breakpoint untuk monitor sangat lebar, misalnya @media (min-width: 1400px).
  2. Mengubah breakpoint tablet dari 768px menjadi 900px, lalu mengamati perubahan susunan kartu.
  3. Menerapkan pola table-responsive atau pembungkus overflow pada konten yang melebar.
  4. Menguji posisi label hamburger dan memastikan selector tetap sesuai struktur HTML.
  5. Membandingkan pendekatan desktop-first dengan mobile-first.
Checklist responsif: tidak ada konten terpotong, tabel dapat digeser bila terlalu lebar, form tidak keluar dari layar, dan navigasi masih dapat digunakan dengan nyaman.
Jobsheet 04

Penyempurnaan Layout dan Komponen

Tahap ini meneruskan pola halaman SIMPUS-Mini dan memantapkan konsistensi tampilan antarhalaman.

Bagian yang perlu dijaga

  • Header, navigasi, judul halaman, area konten, dan footer mempunyai pola visual yang konsisten.
  • Halaman daftar buku dan daftar anggota menggunakan struktur tabel yang mudah dibaca.
  • Halaman tambah buku dan tambah anggota memiliki label yang jelas serta jarak input yang rapi.
  • Warna tombol aksi dibedakan dengan jelas, tetapi tetap konsisten di semua halaman.
  • Perubahan CSS tidak boleh merusak fungsi tautan, nama field, ID elemen, atau struktur data.
Catatan laporan: berkas “Laporan Jobsheet 4.md” di arsip hanya memuat identitas praktikan tanpa rincian tugas. Bagian ini adalah rangkuman penghubung berdasarkan struktur proyek Jobsheet 4, bukan daftar klaim perubahan spesifik.
Jobsheet 05

JavaScript untuk Interaksi Halaman

JavaScript membuat halaman bereaksi terhadap tindakan pengguna tanpa harus menulis ulang seluruh HTML secara manual.

Materi utama

  • DOM: memilih dan mengubah elemen HTML melalui JavaScript.
  • Event: merespons input pencarian, klik tombol, dan pengiriman form.
  • Validasi form untuk mendeteksi field wajib yang masih kosong.
  • Filter tabel berdasarkan isi kolom tertentu.
  • Counter yang menampilkan jumlah baris yang terlihat dibanding jumlah awal.
  • Animasi menu navigasi menggunakan class dan CSS transition.

Perubahan yang tercatat

  1. Menambahkan validasi ISBN: jika diisi, karakter yang diperbolehkan adalah angka dan tanda hubung.
  2. Menambahkan transisi pada menu navigasi agar perubahan buka/tutup terasa lebih halus.
  3. Memperluas filter tabel agar pencarian dapat dibatasi pada kolom Judul.
  4. Menambahkan counter seperti “Menampilkan 3 dari 5 buku”.
  5. Memperbarui counter setelah filter atau penghapusan baris.
  6. Merangkum field wajib ke dalam array dan memeriksanya menggunakan forEach().

Contoh pola logika

const fieldWajib = ["judul", "pengarang", "tahun", "stok"];

Daftar field dikelola dalam satu array. Perulangan memeriksa setiap field sehingga validasi lebih ringkas dan mudah dikembangkan.
Perhatian: validasi JavaScript meningkatkan pengalaman pengguna, tetapi untuk aplikasi yang sudah menggunakan backend, validasi sisi server tetap diperlukan karena validasi browser dapat dilewati.
Jobsheet 06

JSON, Fetch API, dan Data Dinamis

Data dipisahkan dari tampilan sehingga daftar buku dan anggota dapat dibaca dari berkas JSON, lalu ditampilkan ke halaman dengan JavaScript.

Struktur berkas

data/buku.jsonMenyimpan kumpulan data buku dalam format JSON.
data/anggota.jsonMenyimpan kumpulan data anggota dalam format JSON.
assets/js/buku.jsLogika khusus untuk halaman dan data buku.
assets/js/anggota.jsLogika khusus untuk halaman dan data anggota.

Alur kerja

  1. Browser membuka halaman HTML.
  2. File JavaScript menjalankan fetch() untuk mengambil berkas JSON.
  3. Respons dibaca sebagai JSON menggunakan response.json().
  4. JavaScript membuat atau memperbarui baris tabel dari data yang diterima.
  5. Fitur pencarian, validasi, konfirmasi hapus, dan tombol aksi menangani interaksi pengguna.

Hal yang perlu dipahami

  • JSON adalah format pertukaran data, bukan database yang otomatis menyimpan perubahan.
  • fetch() bekerja secara asinkron; tangani kegagalan jaringan atau respons yang tidak berhasil.
  • Periksa jalur relatif file JSON berdasarkan lokasi halaman yang sedang dibuka.
  • Aksi hapus yang hanya menghilangkan baris dari DOM belum tentu mengubah isi file JSON secara permanen.
  • Untuk penyimpanan permanen, diperlukan backend atau API yang menyediakan operasi baca dan tulis data.
Penting: berdasarkan struktur proyek, Jobsheet 6 menggunakan data JSON dan JavaScript di browser. Jangan menganggap perubahan data sudah tersimpan permanen hanya karena baris tabel menghilang dari layar.
Navigasi proyek

Struktur Folder yang Umum

Setiap jobsheet memiliki folder tersendiri agar perkembangan kode bisa dibandingkan dari tahap ke tahap.

projek-danielramadhaniz-main/
├── jobsheet-01/ — HTML dasar
├── jobsheet-02/ — HTML dan CSS
├── jobsheet-03/ — responsive design
├── jobsheet-04/ — penyempurnaan halaman
├── jobsheet-05/ — JavaScript interaktif
└── jobsheet-06/ — JavaScript dan data JSON

Contoh bagian dalam folder Jobsheet 6

  • index.html — halaman beranda.
  • buku/list.html dan buku/tambah.html — halaman buku.
  • anggota/list.html dan anggota/tambah.html — halaman anggota.
  • assets/css/style.css — aturan tampilan.
  • assets/js/ — file JavaScript aplikasi.
  • data/ — data buku dan anggota dalam format JSON.
Jika tautan atau CSS tidak terbaca setelah folder dipindahkan/diubah nama, periksa kembali jalur relatif seperti ../assets/css/style.css dan tujuan tautan menu.
Sebelum dikumpulkan

Checklist Pengujian

  • Semua tautan menu membuka halaman yang benar, khususnya Daftar Anggota tidak mengarah ke Daftar Buku.
  • Header, judul, tombol, tabel, dan form memiliki gaya yang konsisten.
  • Jumlah kolom header tabel sesuai dengan sel pada setiap baris.
  • Form memiliki label dan tipe input yang sesuai.
  • Pencarian hanya memfilter data sesuai aturan yang diinginkan.
  • Counter diperbarui setelah pencarian dan penghapusan baris.
  • Menu hamburger dapat dibuka dan ditutup pada layar sempit.
  • Tidak ada horizontal overflow yang tidak disengaja pada tampilan mobile.
  • Fetch JSON tidak menghasilkan error; periksa jalur data dan Console browser.
  • Aksi yang belum menyimpan data secara permanen diberi pemahaman yang tepat.

Langkah pemeriksaan di browser

  1. Jalankan proyek melalui server lokal yang sesuai, terutama saat memakai fetch().
  2. Buka setiap halaman dari menu navigasi, bukan hanya mengetik URL satu halaman.
  3. Uji form dengan data valid, field kosong, dan format yang salah.
  4. Uji pencarian dengan kata yang cocok dan kata yang tidak cocok.
  5. Ubah ukuran browser ke desktop, tablet, lalu ponsel.
  6. Buka Developer Tools → Console dan Network jika CSS, JavaScript, atau JSON gagal dimuat.
